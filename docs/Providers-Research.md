# Provider interfaces and reviewed limits

Reviewed against vendor documentation and upstream sources on 2026-10-05. This is an implementation audit, not proof of connectivity to a lab VPN. Automated tests can validate provisioning and parsing without a gateway; a real connection still requires a configured Windows host, drivers, server and credentials.

## Windows native VPN

The console creates only its own per-user `CNIT455-<profile GUID>` entry. `Add-VpnConnection` provisions L2TP/IPsec with a PSK and MSCHAPv2, SSTP with MSCHAPv2, or IKEv2 with EAP. `Add-VpnConnectionRoute` supplies explicit protected networks. Actual connection and assigned IP are read back; a successful provisioning operation is not a successful tunnel. Existing unrelated current-user and all-user entries are not edited. Server authentication must permit the selected method; PAP-only legacy L2TP servers are not supported by this adapter. No global IPsec or firewall changes are made. [Microsoft VPN cmdlet reference](https://learn.microsoft.com/en-us/powershell/module/vpnclient/add-vpnconnection?view=windowsserver2025-ps).

The native adapter passes username/password to `RasDialW` in memory, not through process arguments. Its structure follows the Windows SDK `RASDIALPARAMSW` layout, including pointer-sized callback and encrypted-password fields. Callback delegates remain rooted through disconnect, with Microsoft's documented three-second post-hangup resource boundary. Only disconnect uses `rasdial`, with the app-owned name and no credentials. [Windows SDK header](https://github.com/microsoft/win32metadata/blob/main/generation/WinSDK/RecompiledIdlHeaders/um/Ras.h), [RasHangUp guidance](https://learn.microsoft.com/en-us/windows/win32/api/ras/nf-ras-rashangupw).

The IKEv2 branch opens the Windows authentication dialog and reports external-client status until Windows reports a connection. Automatic EAP policy, client-certificate selection and trust provisioning are not implemented. Certificate inventory/import does not imply that a native profile uses that certificate. Use a reviewed Windows profile/client for custom EAP or machine-certificate policy. This adapter never substitutes IKEv2 for the lab's potentially different IKEv1/XAUTH requirement.

Static PowerShell scripts receive JSON on stdin; secret values are absent from command-line arguments. Windows necessarily retains the L2TP PSK in its protected VPN configuration while that profile exists. Explicit disconnect removes the temporary profile. Closing/crashing the console can leave a Windows-managed profile/tunnel; reopen and disconnect or remove the app-owned entry in Windows VPN settings.

## WireGuard for Windows

The reviewed vendor interfaces are `wireguard /installtunnelservice <file>`, `/uninstalltunnelservice <name>`, and `/dumplog /tail`. Each app profile has an isolated `WireGuardTunnel$cnit455-...` service. `wg show <name>` exposes endpoint, public key, AllowedIPs, handshake and transfer counters without requesting secret-bearing `dump` output. Keypair/PSK creation uses `wg genkey`, `wg pubkey` and `wg genpsk`; no cryptography is reimplemented. [Official Windows enterprise guide](https://git.zx2c4.com/wireguard-windows/about/docs/enterprise.md), [WireGuard quick start](https://www.wireguard.com/quickstart/).

Service configuration uses `.conf.dpapi` with the tunnel name as the DPAPI description and ACL access limited to the current account, SYSTEM and administrators. Machine-scoped protection lets the SYSTEM tunnel service read it. This format and name check match WireGuard's documented contract and upstream decryptor. The service and encrypted file intentionally survive application exit. Disconnect removes the service and session-owned file. After a crash/restart, old encrypted Runtime directories may require manual cleanup after removing the associated service. [Upstream DPAPI implementation](https://github.com/WireGuard/wireguard-windows/blob/master/conf/dpapi/dpapi_windows.go).

Administrator rights are required for installation/removal. Imported configurations reject command hooks and unsupported directives, validate keys/addresses/endpoint syntax, and require an added peer PSK in Lab Mode. A recent observed handshake produces connected status; missing/stale handshake remains connecting/unknown. One peer's handshake does not prove every peer or destination works. Full-mode generated AllowedIPs include IPv4 and IPv6 defaults; this does not prove that IPv6 is assigned, routed or reaches the Internet. Inspect both address families on the test host.

## OpenVPN Community

The adapter runs a separately installed Community `openvpn.exe` process; OpenVPN Connect's distinct management APIs are outside this implementation. It accepts self-contained TLS client exports, including inline CA/certificate/key blocks. Scripts, plugins, external credential/key files, static-key mode, encrypted private keys and unknown directives are rejected. The app forces server-certificate verification, TLS 1.2 minimum, auth-nocache and restricted script security. Supported authentication is inline certificate, username/password, or both; interactive MFA/challenge and smart-card PIN prompts require the vendor client. [OpenVPN 2.6 manual](https://openvpn.net/community-docs/community-articles/openvpn-2-6-manual.html).

The local management socket binds to loopback, requires a random password in an ACL-protected temporary file, and is checked against the launched process's TCP owner before any credentials are sent. The management reader answers ordinary Auth prompts and reads state/log events; only observed `CONNECTED,SUCCESS` becomes connected. Credentials are quoted according to the management protocol and never logged. Disconnect sends SIGTERM and terminates only the app-owned process if graceful shutdown times out. Normal app shutdown removes the copied profile and credentials. [Official management interface](https://openvpn.net/community-docs/management-interface.html).

An abrupt crash may leave an ACL-protected Runtime directory containing the copied inline key and an OpenVPN process. Reboot/stop that specific engine before removing its orphan directory; never upload Runtime files as evidence. Original imported files remain the user's responsibility. Route policy comes from the imported configuration/server and must be compared with the desired policy in Diagnostics. Installation of OpenVPN drivers and UAC elevation are explicit user/admin actions, never silent installation.

## Shrew Soft

The vendor's published stable release is 2.2.2 from July 2013, with Windows support listed through Windows 8. Windows 11 compatibility cannot be promised. The feature matrix includes XAUTH, Mode Config, NAT-T and split tunneling, but a running executable/service does not prove driver compatibility. Detection checks standard Program Files paths and enumerates matching service status without starting/stopping shared services. [Official downloads/support matrix](https://www.shrew.net/download/vpn).

The adapter opens `ipsecc.exe -r <site name>` without passwords or automatic authentication. The name must already be present in Shrew VPN Access Manager. Selecting a `.vpn` file without a site name opens Access Manager and explains its File > Import workflow. The console does not invent the internal PSK encoding or mutate vendor settings. Disconnect is performed in Shrew's own window; its maintainer documented the absence of a CLI disconnect option. It would be unsafe to replace this with stopping shared services or killing every client process. [Maintainer's CLI discussion](https://lists.shrew.net/pipermail/vpn-help/2009-December/011062.html), [Shrew administration guide](https://www.shrew.net/static/help-2.2.x/pdf/Shrew%20Soft%20VPN%20Client%20Administrators%20Guide.pdf).

Status remains UNKNOWN. Inspect Shrew's connection status, use its VPN Trace tool, and paste relevant output for redaction. No background log scraping, silent password storage or fabricated tunnel success is performed. This is a limited but usable profile-launch adapter, not a modernized Shrew engine.

## NCP Secure Entry

NCP's current download page lists Windows 11 support, and its product comparison advertises API/command-line tools. This research did not establish a current, version-specific, profile-scoped control/status contract or a secure credential transfer contract that could be validated on the build host. Legacy references to `rwscmd /disconnect` describe a global current connection, which cannot establish ownership. The application therefore detects the standard `NCP\\SecureClient\\ncpmon.exe` installation and matching services, then opens the monitor without credentials or unverified switches. [Official downloads](https://www.ncp-e.com/en/service-resources/download-vpn-client), [NCP feature comparison](https://www.ncp-e.com/fileadmin/_NCP/pdf/library/technicalpapers/Comparison_Entry_Enterprise_Clients.pdf).

Connect, profile import, licensing and disconnect are completed in NCP. The adapter reports UNKNOWN and requires routing/connectivity evidence. A future NCP automation adapter must be validated against the installed release's vendor API and must prove that disconnect affects only its own profile. Commercial binaries and licenses are neither embedded nor redistributed.

## Detection and privileges

Providers are separate implementations of `IVpnProvider`. Protocol compatibility, actual dependency detection and adapter limitations are exposed independently. There is no automatic IKEv1/IKEv2 substitution. A missing provider leaves the rest of the app functional. Executables are resolved only from explicit Windows system/Program Files locations, never PATH, a downloaded executable or a shell-expanded profile field. Paths and installed versions are displayed; a detected file is not proof that its signature/driver or server is trusted. Install engines only from the vendor's official package.

The app starts without elevation. WireGuard/OpenVPN actions explicitly require an administrator session in this release; a separate elevated action broker is not implemented. Native current-user profiles and external interactive handoff can operate without globally elevating the app. No telemetry, firewall disablement, driver auto-install or server changes are part of any provider.
